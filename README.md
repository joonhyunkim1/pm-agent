# pm-agent

내 프로젝트들을 지켜보고, 비용을 따져 개선하는 AI 프로젝트 매니저.

현재 단계는 **P1 (제안)** 이다. 결정론적 체크로 "조용히 죽어 있는 것"을 찾아 알리고(P0),
그 결과를 LLM이 읽어 비용이 붙은 개선 제안을 만든다. 승인은 대시보드·Telegram 버튼·CLI에서 한다.

| 단계 | 내용 | 상태 |
|---|---|---|
| P0 관찰 | 매니페스트 · 스캐너 · Finding · 알림 · 대시보드 · 자동 실행 | ✅ |
| P1 제안 | LLM 플래닝 → 제안 카드(비용 범위·기대효과) → 승인 인박스 | ✅ |
| P2 실행 | 코딩 에이전트 실행기 · worktree 격리 · 검증 · PR · 비용 원장 | 예정 |
| P3 LLM 앱 특화 | 새 모델 감지 → 평가셋 A/B → 교체 제안 | 예정 |
| P4 사업 레이어 | 실제 지표 기반 ROI · 검증 실험 보고서 | 보류 (수익 프로젝트 생기면) |

## 설치

```bash
uv tool install --editable ~/Projects/pm-agent   # 어디서나 `pm` 사용
cd ~/Projects/pm-agent/web && npm install && npm run build   # 대시보드
```

## 자주 쓰는 명령

```bash
pm init --all            # Projects 아래 새 폴더를 찾아 매니페스트 초안 생성
pm scan                  # 지금 스캔 (LLM 호출 없음)
pm status                # 프로젝트별 신호등
pm serve --open          # 대시보드 http://localhost:8765
pm digest                # 일일 요약 미리보기
pm idea add "제목" -n "메모"

pm plan --dry-run        # 제안 만들기 전 예상 비용만 보기
pm plan                  # 예상 비용 확인 후 제안 만들기 (변화 있는 프로젝트만 호출)
pm proposals             # 결정 대기 중인 제안
pm approve <ID>          # 승인 → 작업 지시서 생성 (reject / defer도 있음)
pm task <ID>             # 작업 지시서 출력 (Codex·Claude Code에 붙여넣기)
pm usage                 # LLM 비용 원장
```

## 처음 한 번 설정

```bash
# 1) Telegram 알림 — @BotFather에서 /newbot으로 봇을 만든 뒤
pm secret set TELEGRAM_BOT_TOKEN   # 토큰 입력 (화면에 안 보임, 키체인에 저장)
#    새 봇에게 아무 메시지나 보낸 뒤
pm telegram link

# 2) DR 헬스체크 — Vercel 배포 주소 (GitHub secret SITE_URL과 같은 값)
pm secret set DR_SITE_URL

# 3) OpenAI 키 — pm-agent 전용 프로젝트 키 권장 (OpenAI 쪽에도 월 예산 한도를 걸어 둔다)
pm secret set OPENAI_API_KEY

# 4) 자동 실행 — 매시간 헬스체크, 6시간마다 전체 스캔, 48시간마다 제안, 매일 09시 요약
#    + Telegram 버튼을 처리하는 상시 봇
pm schedule install
```

## 구조

```
pm/
  manifest.py      프로젝트별 목표·정책·체크 정의 (pydantic)
  discovery.py     폴더를 보고 매니페스트 초안 생성 (규칙 기반)
  checks/          git · hygiene · npm · python · gh_workflow · http_json · gh_deployment · verify · llm_models
  scanner.py       체크 실행 → Finding 갱신 → 알림 / tick(스케줄러 진입점)
  store.py         SQLite: 스캔 이력, Finding 수명주기, append-only 이벤트
  notify/          즉시 알림(critical만) + 일일 요약
  planner.py       제안 만들기: 맥락 구성, 변화 감지, 제안 카드
  llm.py           LLM 호출: 예산 확인 → 호출 → 비용 원장
  pricing.py       가격표·비용 계산 (data/openai_prices.json)
  proposals.py     승인·거절·보류, 작업 지시서
  notify/bot.py    Telegram 버튼·명령을 처리하는 상시 봇
  schedule.py      launchd (macOS) / 작업 스케줄러 (Windows, 미검증)
  api.py           대시보드용 로컬 API (127.0.0.1)
web/               React + Vite 대시보드 (나중에 Tauri로 감싸기 쉬운 정적 SPA)
```

설정·매니페스트·DB는 레포가 아니라 앱 데이터 폴더에 있다(`pm config`로 위치 확인).
관리 대상 중 public 레포가 있어서, 예산·정책을 레포에 넣으면 그대로 공개되기 때문이다.

## 스캔 주기

| 종류 | 주기 | 체크 |
|---|---|---|
| 헬스 스캔 | 매시간 (tick마다) | 예약 워크플로우 성공률, HTTP 헬스 엔드포인트, 배포 연속 실패 |
| 전체 스캔 | 6시간 (`scan_interval_hours`) | 위 항목 + git 상태, 비밀값 위생, 의존성·취약점, 테스트·빌드, LLM 모델 목록 |

서비스 장애는 가볍고 급한 헬스 체크로 1시간 안에 잡고, 느리고 급하지 않은 점검은 전체 스캔에 모았다.
노트북이 잠들어 있어도 다음 tick에서 밀린 스캔을 따라잡는다.

## 제안 (P1)

```
전체 스캔 결과 ─(변화 있는 프로젝트만)→ LLM 플래너 → 제안 카드 → 승인함(대시보드 · Telegram 버튼 · CLI)
                                                              └ 승인 → 작업 지시서 (실행은 P2)
```

- **호출 조건**: 48시간(`llm.plan_interval_hours`)마다, 지난 계획 이후 열린 문제·커밋·매니페스트·사용 모델이
  바뀐 프로젝트만 호출한다. 변화가 없으면 0원. L0 프로젝트와 아이디어 단계는 제외.
- **보내는 것**: 매니페스트, 열린 문제, 체크 요약, 최근 커밋, README 앞부분, `.gitignore`를 따르는 파일 구조.
  `.env`, 제외 경로(`data/` 등), 코드 본문은 보내지 않는다. OpenAI 쪽에 대화를 저장하지 않는다(`store=false`).
- **금액은 코드가 계산한다**: LLM은 작업 규모(S/M/L)와 가정만 정하고, 실행 비용 범위·상한은
  `pm/data/openai_prices.json`(공식 가격 페이지 Standard 표, 기준일 표시)로 계산한다.
  실측 원장이 쌓이기 전까지 실행 비용은 "기본 가정"으로 표시한다.
- **예산**: 호출 전에 최악의 경우 비용이 월 한도(`llm.monthly_budget_usd`, 기본 $10)를 넘으면 호출하지 않는다.
  모든 호출은 성공·실패와 상관없이 원장(`pm usage`, 대시보드 스캔 이력 탭)에 남는다.
- **승인 피로 방지**: 한 번에 프로젝트당 최대 3개, 전체 최대 5개만 승인함에 올리고 나머지는 백로그.
- **저위험 표시**: 유지보수 · 규모 S · 위험 낮음 · 보호 경로 없음 · 실효 L3 → P2 이후 자동 처리 대상.

### 비용 최적화 실측 (2026-09-23, 5개 프로젝트, 같은 입력)

| 조합 | 비용 | 기준 대비 | 결과 |
|---|---|---|---|
| 기준선: gpt-6-sol Standard, 자동 캐시 | $0.1044 | — | 비용의 62%가 출력(그중 35%가 추론), 입력 대부분이 캐시 쓰기 할증(1.25배) |
| **A. Flex + 명시 캐시 (채택)** | **$0.0476** | **−54%** | 같은 모델·추론이라 제안 품질 동일. 캐시 쓰기는 공통 앞부분 1,181토큰만 |
| B. A + 추론 `low` | $0.0372 | −64% | 핵심 제안은 같지만 부가 제안 누락·추측성 제안 발생 |
| C. B + 출력 `low` | $0.0308 | −70% | 작업 단계가 짧아지며 **안전 주의사항 누락** (예: "Prisma 다운그레이드 금지") |
| D. gpt-6-luna + Flex + 캐시 | $0.0035 | −97% | 이번 표본에선 주의사항까지 유지. 표본이 작아 기본값으로는 보류 |

- **Flex**: Standard의 정확히 반값. 자원이 없으면 Standard로 한 번 재시도한다(실험 중 실제로 동작 확인).
- **명시 캐시**: GPT-6의 자동 캐시는 프롬프트 전체를 1.25배로 캐시에 쓴다. 공통 지시문 끝에만 캐시 지점을 두면
  프로젝트별 내용은 할증 없이 청구되고, 공통 부분은 다음 호출에서 0.1배로 읽힌다.
  지시문+출력 형식이 1,024토큰보다 짧아지면 캐시가 걸리지 않으니 주의.
- 추론 강도를 낮추는 것은 채택하지 않았다. 작업 지시서는 P2 실행기가 그대로 따르므로,
  몇 센트를 아끼려다 안전 주의사항이 빠지는 쪽이 더 비싸다.
- 비용 미리보기의 출력 토큰은 원장의 최근 실측 중앙값을 쓴다(첫 실행 때 4,000토큰 가정 → 예상이 실제의 2.3배였음).

## 알림 규칙

- **새로 생긴 위험(critical)만 즉시** Telegram으로 보낸다. 같은 문제는 한 번만 알린다.
- 주의·정보 항목은 하루 한 번 요약에 묶는다.
- 대시보드에서 `확인`하면 해결될 때까지 목록에 남지만 다시 알리지 않는다. 더 심각해지면 다시 연다.
- `무시`하면 앞으로 알리지 않는다.

## 자율 수준

`autonomy`는 L0 관찰 / L1 제안 / L2 PR까지 / L3 저위험 자동 머지.
L3는 테스트 + 운영 헬스체크(V2)가 있는 프로젝트에서만 실제로 적용되고, 모자라면 자동으로 L2로 묶인다.
(P0에서는 아직 코드를 고치지 않으므로 표시만 한다.)
